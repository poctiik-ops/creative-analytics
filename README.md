# Creative Analytics

Адаптивный дашборд Unity Ads + Keitaro для Ubuntu 24.04 / Docker Compose / PostgreSQL 16. Расходы и установки из Unity, клики и количество депозитов из Keitaro. Доходы Keitaro не читаются и не сохраняются. Валюта расходов: USD; отчёты: UTC.

## Запуск на VDSina

Рекомендуется Ubuntu 24.04, 2 vCPU, 2 GB RAM, 20 GB SSD, домен. На VDSina создайте сервер, добавьте SSH-ключ, направьте A-запись домена на IPv4 сервера. AAAA добавляйте только при рабочем IPv6.

Установите Docker Engine и Compose plugin по официальной инструкции: https://docs.docker.com/engine/install/ubuntu/ . Не используйте непроверенные install-скрипты. Проверка: `docker compose version` и `docker run --rm hello-world`.

```sh
sudo apt update
sudo apt install -y git openssl ufw
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 443/udp
sudo ufw enable
# Клонируйте репозиторий под отдельным пользователем развертывания.
git clone https://github.com/poctiik-ops/creative-analytics.git
cd creative-analytics
cp .env.example .env
# Укажите DOMAIN и UNITY_ORG_ID в .env (это не секреты).
nano .env
./deploy/init-secrets.sh
# Введите Unity API key непосредственно в файл на сервере, без помещения в команду/историю:
chmod 600 secrets/unity_api_key
nano secrets/unity_api_key
chmod 444 secrets/unity_api_key
docker compose up -d --build
docker compose ps
docker compose logs --tail=50 web worker proxy
```

Caddy получает TLS-сертификат автоматически. Откройте HTTPS на своём домене. Логин `admin`, пароль прочитайте **локально** из `secrets/app_password`. HTTPS обязателен для Basic Auth. Не отправляйте пароль или API key в чат. Для теста без домена задайте `DOMAIN=:80` только в изолированной локальной среде: это HTTP без шифрования.

PostgreSQL и приложение **не публикуют порты хоста**. Из интернета доступны только 80/443 Caddy. UFW сам по себе не блокирует опубликованные Docker-порты; не добавляйте `ports` к db/web. В панели VDSina разрешите входящие SSH (лучше только со своего IP), TCP 80/443 и UDP 443. Не открывайте 5432/8000. Для администрирования БД используйте `docker compose exec db psql -U analytics`.

`secrets/`, `.env`, `backups/` исключены из Git и Docker build context. Секреты Compose — локальные файлы, не шифрованное хранилище; каталог `secrets` имеет 0700, файлы доступны на чтение UID контейнера внутри каталога. Защитите доступ к серверу и резервным копиям. Файлы не перезаписываются генератором. Не коммитьте их даже в приватный репозиторий. Смена db_password в файле не меняет пароль уже инициализированной БД: сначала измените роль внутри PostgreSQL, затем файл и перезапустите сервисы.

## Unity Stats API v2.0

Нужны Organization ID и API key рекламодателя с доступом к статистике. Worker запускается при старте и каждый час, загружает последние 7 завершённых UTC-дней. Перекрывающееся окно обновляет поздние конверсии без накопления дубликатов. `SYNC_LOOKBACK_DAYS` — 1…90, `SYNC_INTERVAL_SECONDS` — минимум 60. Текущий незавершённый день не запрашивается. Кнопка синхронизации использует тот же механизм; advisory lock не допускает параллельную синхронизацию.

Адаптер `app/unity.py`: `https://stats.unityads.unity3d.com/advertiser/v2/organizations/{org}/reports/acquisitions`, API key в query parameter `apikey`, `scale=day`, `groupBy=creativePack,country`, `fields=spend,installs`. Принимает CSV с `timestamp,creativePackId,country,spend,installs` или JSON-массив (либо `data`). Дополнительные измерения агрегируются по дню/pack/GEO. Ошибки HTTP и схемы сохраняются без URL и ключа; старые данные остаются на месте. Пустой отчёт не удаляет ранее полученные записи. Удалённые из источника строки требуют отдельной сверки, автоматического удаления нет.

**Ограничение:** реальный запрос к Unity с ключом ещё не проверен; доступ к документации из среды разработки был заблокирован. Параметры запроса и формат ответа нужно подтвердить на вашем аккаунте перед эксплуатацией. Ошибка или незнакомый формат не должны считаться успешным импортом. Без ключа работает CSV-режим, интерфейс явно показывает отсутствие Unity.

## CSV Keitaro

Экспортируйте **агрегированный** отчёт: дата / creative ID / страна / оффер. В `sub_id_1` должен приходить **Unity creative pack ID**, а не название файла/объявления. Автоматического нечёткого сопоставления нет. Шаблон: [app/static/keitaro-template.csv](app/static/keitaro-template.csv).

Обязательные колонки (регистр заголовков неважен):

| Поле | Допустимые названия |
|---|---|
| Дата YYYY-MM-DD | date, day, дата |
| Unity creative pack ID | creative_id, creative, sub_id_1, креатив |
| Двухбуквенный GEO | country_code, country, geo, страна |
| Оффер | offer, offer_name, оффер |
| Клики | clicks, клики |
| **Количество** депозитов | deposits, conversions, депозиты |

`conversions` разрешено только если отчёт Keitaro отфильтрован **по типу депозит**. Приложение не может определить тип конверсии в агрегированном CSV. Сумма депозитов/выручка не подходит. Все лишние колонки, включая revenue, payout, profit, игнорируются. UTF-8, запятая или `;`, до 10 MB и 100 000 строк. Примерные строки шаблона не загружаются автоматически.

Защита от дубликатов: SHA-256 файла + уникальные ключи PostgreSQL. Повтор того же файла пропускается; новый файл с тем же суточным ключом **заменяет** метрики, не прибавляет их. Дубли ключей внутри файла отклоняются, чтобы не задвоить агрегаты. Ошибка в любой строке отклоняет весь файл. Файл — снимок перечисленных ключей, не полная замена периода: отсутствующие в новом файле ключи не удаляются. Не загружайте перекрывающиеся сегменты как независимые отчёты одного ключа. История хранит время и количество строк, не исходные файлы и не выручку.

## Метрики

Расходы/установки сначала соединяются с **агрегированными по всем офферам** кликами/депозитами по дате/creative/GEO. Это предотвращает умножение расходов при нескольких офферах. Несопоставленные ключи видны, индикатор показывает долю ключей с обоими источниками. CPI = spend/installs; CPA (прокси) = spend/deposits; GEO-матрица = deposits/installs × 100. При нулевом знаменателе — «—». CPA и отношение депозитов к установкам скрываются при неполном сопоставлении источников. Это агрегатное сопоставление, **не когортная/пользовательская атрибуция**. Временные лаги, разные окна, отсутствие источника и малая выборка искажают отношения. ROI/ROAS не рассчитываются, так как доходов нет. Рейтинг сортируется по расходам, CPI, депозитам или депозитам на 100 установок. Офферы показывают только Keitaro; распределение расходов по офферам не выдумывается.

## Проверки и разработка

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest -q tests/test_imports.py
# Интеграционные тесты ОЧИЩАЮТ таблицы. Только отдельная тестовая БД!
DB_HOST=127.0.0.1 DB_PORT=15432 DB_NAME=analytics DB_USER=analytics \
DB_PASSWORD=local-test-password APP_PASSWORD=test-password-123456789 \
RUN_DB_TESTS=1 .venv/bin/pytest -q
```

Тесты проверяют валидацию CSV, игнорирование выручки, дедупликацию, атомарность, авторизацию, CSRF, отсутствие умножения расходов при нескольких офферах, несопоставленные ключи. `/health` проверяет доступность БД; не подтверждает работоспособность Unity. Приложение использует существующий checkout; отдельные worktree для запуска не нужны.

## Резервные копии и обновление

```sh
./deploy/backup.sh
# Восстанавливайте сначала в отдельной БД для проверки:
docker compose exec -T db createdb -U analytics analytics_restore
# Замените имя файла на нужный dump:
docker compose exec -T db pg_restore -U analytics -d analytics_restore < backups/FILE.dump
# Проверка данных; затем удаление только тестовой БД после проверки.
docker compose exec db psql -U analytics -d analytics_restore -c 'SELECT count(*) FROM unity_daily;'
# Перед обновлением — backup; затем:
git pull --ff-only
docker compose up -d --build
```

Настройте ежедневный запуск `deploy/backup.sh` через cron/systemd и копирование dump на отдельное защищённое хранилище; это не включается автоматически. Проверяйте восстановление. `docker compose down` сохраняет тома; **не используйте `down -v`** на рабочем сервере. Начальная схема создаётся идемпотентно под блокировкой; для будущих изменений схемы понадобятся версионированные миграции. Образы используют major-теги: перед эксплуатацией закрепите проверенные digest для своей архитектуры и регулярно устанавливайте security updates.

Развёртывание на реальном VDSina требует вашего сервера, DNS и секретов. Проект подготавливает конфигурацию, но сам не создаёт платные ресурсы и не загружает секреты в GitHub.
